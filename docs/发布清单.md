# BiliNotes 发布清单（给别人装）

从"我电脑上能跑"到"别人电脑上能跑"，中间要做的事都在这页。做完一项勾一项。

## 一、构建产物（本机操作）

```bat
:: 0. 旧产物挪走（见下方坑）
move dist\BiliNotes dist\BiliNotes.old-日期

:: 1. 打包主程序（onedir，产物 dist\BiliNotes\）
python -m PyInstaller build.spec --noconfirm

:: 2. 验收：必须 34 项全绿，有一项 FAIL 就不要往下走
python tools\verify_bundle.py

:: 3. 编译安装包（产物 installer\dist\BiliNotes-setup-<版本>.exe）
"%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe" installer\BiliNotes.iss
```

> **坑 1**：PyInstaller 收尾会删旧 dist 再重建。删大量文件被安全软件拦下时，
> 它仍显示 `Build complete!` 但产物是旧的。打包前先手动把 `dist\BiliNotes` 改名挪走。
> **坑 2**：`build.spec` 末尾有一段「统一 VC++ 运行库」的后处理，千万别删，理由见第三节。

最终交付物只有一个文件：`BiliNotes-setup-<版本>.exe`（内含程序、ffmpeg、VC++ 运行库）。
2026-11-10 最终实测：`BiliNotes-setup-0.2.4.exe` **210.8MB**（220,994,966 字节），
SHA256 `f93e06008af37ba14b0bdb90c36aac6f8fb6a68841c75138b8c11c72641f834c`；
`verify_bundle.py` 完整验收 **34 项全绿**（版本号三处一致：healthz / settings / update 都是 0.2.4），
另跑 `verify_fresh_install.py` 新机模拟 17 项全绿、`check_api_contract.py` 前后端接口契约一致。
**这是首个对外 Release 该用的包**：`__update_repo__` 已写死 `jinmm1233/bili-notes`，
更新器也修好了 SHA256SUMS 校验、多 exe 资产选择、Range 断点续传与 404 提示。
建 Release 用 tag `v0.2.4`，资产传这个 exe + `SHA256SUMS.txt`，说明贴
`release-notes-0.2.4.md`（旧教程里的 `v0.2.2` / `v0.2.3` 作废）。
（0.2.2 新增知识库三级浏览：同一合集折成一张卡，点进去按集数看全部分集；
0.2.1 修了无语音视频「有画面却生成不了笔记」和误报未配置模型、重复双击只切前台；
0.2.0 已含内置更新、版本号统一、零后台入口说明、设置页提速、本机请求绕开代理、
笔记详细度三档与「画面停住取完整帧」、白窗口根治——端口探测改 `connect_ex`、
单实例改命名互斥量、服务起不来绝不开窗口。）
编译日志里逐个确认了 `_internal/msvcp140.dll`、`python313.dll`、`bin/ffmpeg.exe`、
`onnxruntime_pybind11_state.pyd`、`web/index.html`、`redist/vc_redist.x64.exe` 都在包里。

> **打包前必做**：先把 `dist\BiliNotes` 改名挪走（`move dist\BiliNotes dist\BiliNotes.old-日期`）。
> PyInstaller 收尾的 `Removing dir` 是 2500+ 文件的批量删除，会被安全策略拦下，
> 命令以 `exit=1` 结束、`dist\BiliNotes` 还是旧包——这次就撞上了（见坑 1）。

## 三、两个曾经让打包版"静默崩溃"的坑（别再踩）

这两条都是**原生段错误**，不弹 Python 报错框，日志停在启动成功那一行，最容易误判成"已经好了"。

1. **包内混进旧版 `msvcp140.dll`**：`collect_all` 把某依赖 vendor 的
   `msvcp140.dll 14.26`（VS2019）带进 `_internal`，而系统是 14.51。Windows 优先加载
   程序目录里的旧版 → `onnxruntime 1.31` 在 import 时 access violation →
   **画面取字（OCR）整个不能用**，启动后台自检也会把主进程带崩。
   `build.spec` 末尾现在用 `System32` 的同名文件覆盖包内副本；
   `verify_bundle.py` 会逐个比对哈希。
2. **不要在主进程里做重型库自检**：`envcheck.probe()` 改成起子进程探
   （`BILINOTES_PROBE` 复用同一个 exe，见 `entry.py`）。子进程崩了主程序照常跑，
   还能把"缺 VC++ / 被杀软拦 / 加载崩溃"分清楚。

顺带：`console=False` 时 `sys.stdout/stderr` 是 `None`，任何 `print` 都会把进程打死，
`entry.py` 已接到 devnull；段错误取证落在 `%APPDATA%\BiliNotes\logs\crash.log`。

## 四、装到别人电脑前的检查

1. **目标系统**：Windows 10 1809+ / Windows 11，且装有 Microsoft Edge（系统自带）。
   没 Edge 会自动退回默认浏览器，功能一样，只是有地址栏。
2. **杀软误报**：未签名 exe 常被误报。如果对方杀软拦了，加白名单即可；签名后基本消失。
3. **首次转写要联网**：下载语音模型（base 约 140MB，走 hf-mirror）。纯看笔记/刷卡片不需要联网。
4. **B 站下载**：需要网络；部分视频要登录 Cookie（应用内扫码/粘贴）。
5. **验收脚本全绿**再发，别只信 `Build complete!`。
6. **讲清它是本地程序**：关掉窗口程序就退出，浏览器里存的 127.0.0.1 地址随即失效，
   下次从桌面图标或开始菜单打开。软件**不会后台常驻、不会开机自启**——
   这一条不说明，用户会以为「网址又失效了」是故障。

## 五、代码签名（SmartScreen "未知发布者" 警告）

没有签名，用户首次运行会看到蓝色 SmartScreen 提示——**点「更多信息」→「仍要运行」**就能装，
但对不熟电脑的人有劝退风险。要去掉：

- **个人/内部使用**（现在的情况）：不做签名，在给对方的说明里写一句
  「如果 Windows 提示已保护你的电脑，点 更多信息 → 仍要运行」。
- **正式分发**：买代码签名证书（OV 证书约 ¥800~2000/年，EV 更贵但直接消除警告），
  拿到 .pfx 后在 iss 的 [Setup] 加一行再编译：
  ```
  SignTool=signtool sign /fd SHA256 /f cert.pfx /p 密码 $f
  ```

## 六、已知边界（发给别人前要说的）

- ffmpeg 随包按 **GPL 协议**分发（gyan.dev 构建）。自己用、送朋友没问题；
  若要公开收费分发，需要遵守 GPL（开源对应部分源码）。
- 模型文件（Whisper）不随包：首次转写时下载，装到 `%APPDATA%\BiliNotes\models\`。
- 手机访问依赖同一 WiFi 且路由器不开「设备隔离」；校园网常见隔离，换热点即可（设置页有自检）。
- 未签名，首次运行会有 SmartScreen 提示（见上一节）。中文语言包缺 3 条签名校验
  相关消息（`VerificationKeyNotFound` 等），会显示英文兜底；未签名场景不会触发这几句。
- 包内 VC++ DLL 取自构建机系统（14.51），安装包另带微软官方 vc_redist（14.44）。
  两者向后兼容；若目标机系统已有更新的运行库，安装程序会跳过降级安装。
- 语音转写 / 画面取字用的是 CPU，长视频会比较慢；模型下载失败或杀软拦截时，
  设置页的「环境自检」会指出具体原因。
- **关窗即退（零后台）**：关掉窗口后，浏览器书签和手机扫码的局域网地址都会失效，
  这是本地服务的固有性质，不是故障。正确入口是桌面图标 / 开始菜单。
- **内置更新依赖 GitHub**：国内网络可能连不上 `api.github.com`，此时只显示一行提示，
  不影响使用。可在设置页填下载镜像，或点「查看发布页」自己去下安装包。

## 八、内置更新怎么发版

### 8.0 第一次：源码传到 GitHub（已完成 · 2026-11-09）

实际仓库：**https://github.com/jinmm1233/bili-notes**，已确认 `Public`、
默认分支 `master`，源码 501 文件 / 31.5MB、两次提交。`.gitignore` 已挡住
`dist/`、`installer/dist/`、`bin/`、`.cache/` 等 2.8GB 构建产物——**安装包不进 git，
只作为 Release 资产上传**（仓库单文件上限 100MB，Release 资产可用到 2GB）。

走的是 GitHub Desktop 路线（本机已装 3.6.10，桌面有快捷方式）：
`Add local repository` 选本目录 → `Publish repository` 时**取消勾选
Keep this code private**，浏览器 OAuth 登录即可，不需要手动生成访问令牌。

两个坑：
- 推送报 `fatal: ... Recv failure: Connection was reset` = **代理没开**。
  开 iKuuuVPN 的「系统代理」（`127.0.0.1:7890`，`ProxyEnable=1`）后重试即成功；
  小的 `git ls-remote` 裸连能通，但 31.5MB 推送会被重置，别以为网络是好的。
- 仓库**必须 Public**：私有仓库的 Release 资产要登录才能下载，程序匿名请求
  只会拿到 404，内置更新等于废掉。

`app/__init__.py` 的 `__update_repo__` 已写死 `jinmm1233/bili-notes`，
别人装了包不用自己填；也可以在「设置 → 软件更新」里改（优先级更高）。

### 8.1 以后每次发版

一次完整发版（假设要发 `0.2.3`）：

1. **改两处版本号**（必须一致，否则更新会永远误报）：
   `app/__init__.py` 的 `__version__` 和 `installer/BiliNotes.iss` 的 `MyAppVersion`。
   `/healthz`、`/api/settings`、`/api/update/status` 都读前者，验收脚本会比对三处。
2. 按第一节打包 → `verify_bundle.py` 全绿 → 编译安装包。
3. 跑 `python tools/release_assets.py`：自动算 SHA256，生成
   `installer/dist/SHA256SUMS.txt` 和 `release-notes-0.2.3.md`。
4. 在 GitHub 建 Release：tag 写 `v0.2.3`（可带 `v`，程序会剥掉），
   把安装包与 `SHA256SUMS.txt` 一起拖进资产区，把说明整篇贴进描述框，
   点 Publish release。**主安装包名必须以 `.exe` 结尾**；若同时挂了
   `vc_redist.x64.exe`，程序会优先挑名字带 `BiliNotes` + `setup` 的那个。
5. 校验值两个来源都会读：Release 说明里的 64 位哈希 > `SHA256SUMS.txt` 对应行。
   校验不过会删掉下载文件、拒绝安装；两个都没贴也能装，界面会明说「未提供校验值」。
   下载中断会带 `Range` 从断点续传，不用重下 210MB；续传后整文件重算哈希。
6. 用户端在「设置 → 软件更新」填 `用户名/仓库名`。也可以写死：
   打包时填 `app/__init__.py` 的 `__update_repo__`，或设环境变量 `BILINOTES_GITHUB_REPO`。
   优先级：设置页 > 环境变量 > 打包默认值。
7. 验收：设置页点「检查更新」，应读到最新的 tag 和 Release 说明；
   当前版本与 latest 相同不弹升级，等发了下一个版本才会提示。
   填错仓库名会明确提示「检查用户名/仓库名」，不会笼统说网络不通。

检查时机：启动后静默查一次（12 小时限频），或设置页手动点「检查更新」。
只比对 `x.y.z` 语义化版本；预发布通道、`latest` 之外的 Release 不认。

几个行为边界：

- 下载直链只认 GitHub 官方域名（或用户自己填的镜像前缀），配置被改成别的站点会被拒。
- 点「安装并重启」会**先关掉应用窗口、退出主进程**，再启动安装器（会弹 UAC）。
  不这么做会撞上 Program Files 里 exe 被占用，安装装一半失败弹错误框。
- 安装包落在 `%APPDATA%\BiliNotes\updates\`，下载新版会清掉旧的；卸载不删这个目录。
- 国内连不上 `api.github.com` 是预期情况：只显示一行「不影响使用，稍后再试」，
  不弹错误、不写入失败状态。「查看发布页」按钮始终可点，可手动下载。
